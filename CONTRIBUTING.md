# Public repository contents

Commit application inputs, licensed assets, reusable tests and fixtures, validation scripts, and reviewed documentation. Keep build products, signing profiles, credentials, raw review captures, device identifiers, local paths, copied diffs, compiler caches, and video production outputs outside Git. `planning/` and `R/` are local working directories; ignoring them does not delete their contents or remove past history. Publish sanitized release and verification summaries under `release-notes/`.

Use explicit path lists when staging. Keep dependent source and tests together; verify build inputs against the tested candidate. Preserve existing Pages sample endpoints and licenses. Changing repository documentation does not authorize an app upload, review submission, price change, or website publication.
