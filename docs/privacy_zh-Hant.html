隱私權政策

隱私權政策

MihirakiPDFViewer 是一款用於輕鬆閱讀 PDF 的應用程式 您的設備。此頁面解釋了該應用程式的哪些訊息 處理以及如何使用該資訊。

總結

該應用程式的基本隱私方法。

PDF內容未寄出去

顯示、搜尋、頁面偵測及相關處理 選定的 PDF 在裝置上處理。

無廣告或分析 SDK

該應用程式不包含第三方 SDK 廣告投放或行為分析。

購買由 Apple 處理

應用程式內購買是透過 Apple 的 StoreKit 進行處理的。 該應用程式不會直接接收付款資訊。

應用程式處理的信息

每個功能可能使用的資訊。

PDF 文件

該應用程式開啟使用文件選擇器選擇的 PDF 文件。 PDF 文字、元資料和頁面資訊用於 觀看功能。

  • PDF 檔案不會上傳到外部伺服器。
  • iCloud Drive 中的 PDF 是根據 Apple 的系統行為載入的。
  • 受保護 PDF 的密碼僅用於解鎖文件。

應用程式設定

顯示設定、封面設定、兩頁視圖、應用程式 圖標設置，並且可以存儲類似的偏好 在設備上。

  • 設定用於恢復應用程式行為。
  • 設定不會傳送到開發人員伺服器。

搜尋詞

PDF 搜尋中輸入的文字用於在 PDF 搜尋中進行搜尋 打開 PDF。搜尋詞不會發送到外部 服務。

應用程式內購買

提示購買狀態可用於購買後 UI 和應用程式圖標更改。

  • 付款資訊由 Apple 管理。
  • 開發商不會收到信用卡號或類似的付款詳細資訊。

支援查詢

如果您透過 GitHub 問題或電子郵件聯絡支援人員， 您發送的訊息可能會根據需要進行審核 回覆或調查問題。

  • 請勿傳送PDF檔案或其內容。聯絡支援前，請先閱讀下方的回報與圖片說明。
  • 裝置型號、作業系統版本、應用程式版本和重現步驟有助於調查。

與第三方共享

您選擇分享或傳送給支援人員的資訊會送達所選收件者，且可能由對方保留。StoreKit購買及iCloud Drive依Apple的處理方式運作。下載範例及開啟外部連結會連線至相關服務業者；其隱私規則及您所選分享目的地的隱私規則均適用。App不會自動向開發者傳送診斷結果。

安全性

PDF 檔案和設定僅根據應用程式的需要進行處理。

您管理的訊息

PDF 檔案和密碼由您的裝置管理， iCloud Drive，或您使用的儲存位置。如果你處理 敏感 PDF、啟用設備密碼、生物識別 身份驗證和 iCloud 帳戶保護。

政策變化

本隱私權政策可能在必要時進行更新。

變更通知

重要變更將在此頁面或在 應用程式。此頁面始終提供最新版本。

裝置端診斷與應用程式日誌

診斷結果保存在目前畫面的記憶體中。選擇分享後，文字包含測試時間、機型名稱及機型識別碼（不是裝置唯一ID）、系統與App版本、總記憶體及可用記憶體，以及不含可用儲存空間檢查的結果。日誌記錄事件類型、時間、數量及處理耗時。App內可檢視及分享的日誌最多保留2,000筆；讀取或記錄時移除超過24小時的記錄，並非在App停止時透過計時器刪除。系統日誌依作業系統的保留規則處理。結果及日誌不會自動傳送。

聯絡方式

對於隱私問題或刪除請求，請聯繫 支持。

聯絡方式

使用 GitHub Issues 或電子郵件。在公共場所發文時， 不包含個人資訊或 PDF 內容。

開啟支援頁面

隱私權政策

可從設定頂端或「應用程式資訊」開啟隱私權政策。無論尚未選取 PDF 或正在閱讀，都不需要購買或登入。

可用儲存空間僅在本裝置上顯示。分享的診斷文字不包含儲存空間檢查、數值及其對整體結果的影響。日誌可能包含處理經過時間，但不包含原始系統運作時間。

閱讀復原功能會在本機儲存文件書籤、頁碼、顯示設定和搜尋詞，不儲存 PDF 密碼。要求下載範例時會連線至 GitHub Releases。開啟本政策或 GitHub Issues 也會連線至外部網站，其營運者可能收到 IP 位址和要求資訊。報告僅分享到您選擇的目的地。外部服務適用各自的隱私權政策。

PDF顯示及搜尋在裝置上處理。閱讀還原會在本機儲存文件書籤、頁面位置、搜尋文字及顯示選項，但不儲存PDF密碼。關閉文件或重設設定會刪除還原記錄，但不會刪除PDF或診斷日誌。部分輸入的PDF會複製到App的Documents儲存區。若要移除本機App資料，請使用系統的「刪除App」，而非保留資料的「卸載App」。外部原始檔及已分享的副本不會因此刪除。沒有專用的日誌刪除按鈕。

開啟範例清單時，應用程式會檢查 GitHub 上是否有最新的目錄 JSON。若更新失敗，應用程式會使用上一次有效儲存的清單或隨應用程式提供的清單。只有在您選擇下載時，才會下載 PDF 檔案。目錄請求會聯絡 raw.githubusercontent.com；PDF 下載會聯絡 GitHub Releases。這些服務可能會收到您的 IP 位址和請求資訊。

支援資訊的保留與刪除

支援資訊僅用於回覆、調查問題及技術性的效能改善。我們不要求填寫真實姓名。如果寄件者的顯示名稱包含真實姓名，只會在回覆與調查所需的期間內，將其保留在原始郵件中，不會抄錄到個別案件的Google Sheets或改善筆記。

原則上不要求提供螢幕截圖。只有在文字無法重現問題且確實需要圖片時，才透過tyamada.support@gmail.com接收。傳送前請遮蔽PDF內容、檔案名稱、姓名、通知，以及調查不需要的其他資訊。 圖片原則上在原始郵件內處理。個別案件的Sheets只記錄調查所需的觀察結果，不存放圖片。

不會將GitHub發文者的姓名或使用者名稱抄錄到案件Sheets或改善筆記中。只有在回覆或調查需要時，才在案件Sheet中保留原始Issue的連結。在仍可透過連結確認發文者的期間內，該記錄會被視為可與其建立關聯的資訊。 請勿在公開Issue中張貼個人資訊、PDF檔案或其內容、檔案名稱或螢幕截圖。

GitHub上的公開貼文與開發者管理的郵件及案件記錄有所區別。刪除我們保存的案件連結，不會刪除公開Issue。對於不在管理範圍內的貼文或服務副本，我們無法保證刪除。能夠追溯至寄件者的報告及案件參照，不會被視為匿名資訊。

刪除的起算點與期限

A. 包含所顯示真實姓名的原始郵件、調查圖片及調查副本：已有回覆或調查結論，且開發者確認沒有剩餘工作之日，視為案件完成日。不會僅因沒有回覆而自動結案。每週檢查期限，在完成後約60天開始刪除，並在90天內確認刪除可管理的記錄，包括相關垃圾桶中的內容。60天不是最低保留期間；提早提出的刪除請求不必等到一般期限才處理。

B. 案件Sheets、觀察結果、Issue連結及接收／刪除記錄：自原始資訊刪除完成日起90天內，確認刪除案件檔案及相關記錄和參照。僅刪除列或儲存格不算完成。這不會延長A的期限，也不允許將原始資訊轉存到這些記錄中。公開Issue仍在線上，不會自動延長我們的案件記錄期限。

C. 一般化的改善筆記只保留原因與修正要點，不含姓名、圖片、貼文URL、案件ID或其他能追溯至原始報告的資訊。不得將其當作A或B記錄的替代保存位置。

例外僅限於持續調查或法律上的必要性。我們記錄原因、範圍及結束條件，最遲每30天及調查結束時重新檢視。必要性消失後，原則上在30天內確認刪除；若原來的90天期限仍有效且較早到期，則以該期限為準。重新開啟案件或適用例外，不會自動重設期限。依Asia/Tokyo時區的日曆日計算。

這些期限適用於開發者能管理的記錄。從服務介面刪除，不保證服務提供者內部的復原副本或裝置備份會在相同期限內實體清除。這些副本及其刪除限制，與我們管理的記錄分開處理。刪除App的本機記錄不會刪除已傳送的報告。

如需諮詢或要求刪除，請聯絡tyamada.support@gmail.com。請僅提供辨識相關案件所需的資訊，不要公開張貼。
