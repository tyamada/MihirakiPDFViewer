Patakaran sa Privacy

Patakaran sa Privacy

Ang MihirakiPDFViewer ay isang app para sa kumportableng pagbabasa ng mga PDF iyong device. Ipinapaliwanag ng page na ito kung anong impormasyon ang app humahawak at kung paano ginagamit ang impormasyong iyon.

Buod

Ang pangunahing diskarte sa privacy ng app.

Ang nilalamang PDF ay hindi ipinadala

Pagpapakita, paghahanap, pagtukoy ng pahina, at kaugnay na pagproseso para sa mga napiling PDF ay hinahawakan sa device.

Walang mga ad o analytics SDK

Hindi kasama sa app ang mga third-party na SDK para sa paghahatid ng advertising o pagsusuri ng pag-uugali.

Ang mga pagbili ay pinangangasiwaan ng Apple

Ang mga in-app na pagbili ay pinoproseso sa pamamagitan ng Apple's StoreKit. Ang app ay hindi direktang tumatanggap ng impormasyon sa pagbabayad.

Impormasyon na Hinahawakan ng App

Impormasyong maaaring gamitin ng bawat feature.

Mga PDF File

Binubuksan ng app ang mga PDF file na pinili gamit ang file picker. Ang tekstong PDF, metadata, at impormasyon ng pahina ay ginagamit para sa mga tampok sa pagtingin.

  • Ang mga PDF file ay hindi ina-upload sa isang panlabas na server.
  • Nilo-load ang mga PDF sa iCloud Drive ayon sa gawi ng system ng Apple.
  • Ang mga password para sa mga protektadong PDF ay ginagamit lamang para sa pag-unlock ng dokumento.

Mga Setting ng App

Mga setting ng display, setting ng cover, two-page view, app mga setting ng icon, at maaaring iimbak ang mga katulad na kagustuhan sa device.

  • Ginagamit ang mga setting para ibalik ang gawi ng app.
  • Ang mga setting ay hindi ipinadala sa isang server ng developer.

Mga Termino sa Paghahanap

Ang tekstong ipinasok sa paghahanap na PDF ay ginagamit upang maghanap sa loob ng binuksan ang PDF. Ang mga termino para sa paghahanap ay hindi ipinadala sa panlabas mga serbisyo.

Mga In-App na Pagbili

Maaaring gamitin ang status ng pagbili ng tip para sa post-purchase UI at mga pagbabago sa icon ng app.

  • Ang impormasyon sa pagbabayad ay pinamamahalaan ng Apple.
  • Ang developer ay hindi tumatanggap ng mga numero ng credit card o katulad na mga detalye ng pagbabayad.

Mga Tanong sa Suporta

Kung makipag-ugnayan ka sa suporta sa pamamagitan ng Mga Isyu sa GitHub o email, ang impormasyong ipapadala mo ay maaaring suriin kung kinakailangan tumugon o mag-imbestiga sa isyu.

  • Huwag magpadala ng mga PDF file o ng nilalaman ng mga ito. Basahin muna ang gabay sa mga ulat at larawan sa ibaba bago makipag-ugnayan sa suporta.
  • Ang modelo ng device, bersyon ng OS, bersyon ng app, at mga hakbang sa pagpaparami ay nakakatulong sa pagsisiyasat.

Pagbabahagi sa mga Third Party

Ang impormasyong pinili mong ibahagi o ipadala sa suporta ay napupunta sa napiling tatanggap at maaari niyang panatilihin. Sinusunod ng StoreKit purchases at iCloud Drive ang paghawak ng Apple. Kumokonekta ang sample downloads at external links sa mga operator ng serbisyo; naaangkop ang kanilang privacy practices at ng napiling sharing destination. Hindi awtomatikong nagpapadala ng diagnostic sa developer ang app.

Seguridad

Ang mga PDF file at setting ay pinangangasiwaan lamang kung kinakailangan para sa app.

Impormasyon na Pinamamahalaan Mo

Ang mga PDF file at password ay pinamamahalaan ng iyong device, iCloud Drive, o ang lokasyon ng storage na ginagamit mo. Kung hawakan mo mga sensitibong PDF, paganahin ang passcode ng device, biometric pagpapatunay, at proteksyon ng iCloud account.

Mga Pagbabago sa Patakaran

Maaaring ma-update ang patakaran sa privacy na ito kapag kinakailangan.

Paunawa ng mga Pagbabago

Ang mga mahahalagang pagbabago ay iaanunsyo sa pahinang ito o sa app. Ang pinakabagong bersyon ay palaging magagamit sa pahinang ito.

On-device na diagnostic at mga log ng app

Nananatili ang resulta ng diagnostic sa memory ng kasalukuyang screen. Kapag piniling ibahagi, kasama sa teksto ang oras ng pagsusuri, pangalan at identifier ng modelo (hindi natatanging device ID), bersyon ng OS at app, kabuuan at available na memory, at mga resulta maliban sa pagsusuri ng libreng storage. Nasa log ang uri ng pangyayari, oras, bilang at lumipas na oras ng pagproseso. Hanggang 2,000 entry ang log na nababasa at naibabahagi sa app; inaalis ang lampas 24 oras kapag binabasa o nagtatala, hindi sa pamamagitan ng timer habang nakahinto ang app. Sinusunod ng system logs ang patakaran ng OS. Hindi awtomatikong ipinapadala ang mga resulta at log.

Makipag-ugnayan

Para sa mga tanong sa privacy o mga kahilingan sa pagtanggal, mangyaring makipag-ugnayan suporta.

Paraan ng Pakikipag-ugnayan

Gumamit ng Mga Isyu sa GitHub o email. Kapag nagpo-post sa pampublikong lugar, huwag isama ang personal na impormasyon o nilalamang PDF.

Buksan ang Pahina ng Suporta

Patakaran sa Privacy

Buksan ang Patakaran sa Privacy sa itaas ng Settings o sa App Information. Maaari itong buksan bago pumili ng PDF o habang nagbabasa, nang walang pagbili o pag-login.

Sa device lang ipinapakita ang libreng storage. Hindi kasama sa ibinabahaging diagnostic text ang pagsusuri ng storage, halaga nito, o epekto nito sa kabuuang resulta. Maaaring kasama sa mga log ang tagal ng pagproseso, ngunit hindi ang raw system uptime.

Para maipagpatuloy ang pagbabasa, lokal na sine-save ang bookmark ng dokumento, pahina, mga setting, at teksto sa paghahanap; hindi sine-save ang password ng PDF. Kumokonekta sa GitHub Releases kapag hiniling ang sample download. Nagbubukas din ng panlabas na website ang patakarang ito at GitHub Issues; maaaring matanggap ng operator ang IP address at impormasyon ng request. Ibinabahagi ang ulat sa pinili mong destinasyon. May sariling patakaran sa privacy ang mga panlabas na serbisyo.

Sa device ginagawa ang pagpapakita at paghahanap sa PDF. Lokal na sine-save para sa pagpapanumbalik ang bookmark ng dokumento, posisyon ng pahina, teksto ng paghahanap at mga opsyon sa pagpapakita, ngunit hindi ang password ng PDF. Binubura ng pagsasara ng dokumento o pag-reset ng settings ang tala ng pagpapanumbalik, hindi ang PDF o diagnostic logs. Kinokopya ang ilang na-import na PDF sa Documents storage ng app. Para alisin ang lokal na datos, gamitin ang pag-delete ng app sa OS, hindi ang pag-offload na nag-iiwan ng datos. Hindi nito binubura ang mga orihinal sa labas o mga naibahaging kopya. Walang hiwalay na button para mag-delete ng logs.

Kapag binuksan mo ang listahan ng mga sample, tinitingnan ng app sa GitHub kung may pinakabagong JSON ng catalog. Kapag nabigo ang pag-update, ginagamit nito ang huling wastong naka-save na listahan o ang listahang kasama sa app. Dina-download lang ang mga PDF file kapag pinili mong i-download ang mga ito. Kumokonekta ang kahilingan para sa catalog sa raw.githubusercontent.com; kumokonekta naman ang mga pag-download ng PDF sa GitHub Releases. Maaaring matanggap ng mga serbisyong ito ang iyong IP address at impormasyon tungkol sa kahilingan.

Impormasyon ng suporta at pagpapanatili

Ginagamit lamang ang impormasyon ng suporta para sa pagtugon, pagsisiyasat ng problema, at teknikal na pagpapahusay ng pagganap. Hindi namin hinihingi ang tunay mong pangalan. Kung kasama ito sa ipinapakitang pangalan ng nagpadala, pinapanatili lamang ito sa orihinal na email hangga’t kailangan para sa pagtugon at pagsisiyasat. Hindi ito kinokopya sa Google Sheets ng bawat kaso o sa mga tala ng pagpapahusay.

Hindi karaniwang hinihingi ang mga screenshot. Tinatanggap lamang ang mga ito sa tyamada.support@gmail.com kung hindi maulit ang problema gamit ang teksto lamang at kailangan ang larawan. Bago ipadala, takpan ang nilalaman ng PDF, mga pangalan ng file, pangalan ng tao, notification, at iba pang impormasyong hindi kailangan sa pagsisiyasat. Karaniwang pinoproseso ang mga larawan sa loob ng orihinal na email. Sa Sheets ng bawat kaso, mga obserbasyong kailangan lamang sa pagsisiyasat ang itinatala, hindi ang mga larawan.

Hindi namin kinokopya ang pangalan o handle ng may-akda sa GitHub sa Sheets ng bawat kaso o sa mga tala ng pagpapahusay. Kung kailangan lamang para sa pagtugon o pagsisiyasat, nagtatago kami ng link sa orihinal na Issue sa Sheet ng kaso. Hangga’t matutukoy ang may-akda sa pamamagitan ng link, maaari pa ring iugnay sa kanya ang tala. Huwag mag-post ng personal na impormasyon, mga PDF file o ng nilalaman ng mga ito, mga pangalan ng file, o mga screenshot sa mga pampublikong Issue.

Magkaiba ang mga pampublikong post sa GitHub at ang email at tala ng kaso na aming pinamamahalaan. Hindi nabubura ang pampublikong Issue kapag binura ang link sa aming kaso. Hindi namin magagarantiya ang pagbura ng mga post o kopya ng serbisyo na wala sa aming kontrol. Hindi namin itinuturing na anonymous ang mga ulat at sanggunian ng kaso na matutunton pabalik sa nagpadala.

Simula at mga takdang panahon ng pagbura

A. Mga orihinal na email, kasama ang ipinapakitang tunay na pangalan, mga larawan at kopya para sa pagsisiyasat: kumpleto ang kaso kapag may tugon o konklusyon ng pagsisiyasat at kinumpirma ng developer na wala nang natitirang gawain. Hindi awtomatikong nagsasara ang kaso dahil lamang walang tugon. Lingguhang sinusuri ang mga takdang panahon. Nagsisimula ang pagbura mga 60 araw matapos makumpleto ang kaso, at kinukumpirma ang pagbura ng mga talang maaaring pamahalaan, kasama ang kaugnay na Trash, sa loob ng 90 araw. Hindi minimum na panahon ng pagpapanatili ang 60 araw; hindi maghihintay sa karaniwang takdang araw ang mas maagang kahilingan sa pagbura.

B. Sheets ng bawat kaso, mga obserbasyon, link sa Issue, at mga tala ng pagtanggap at pagbura: kinukumpirma ang pagbura ng file ng kaso at mga kaugnay na tala at sanggunian sa loob ng 90 araw matapos makumpleto ang pagbura ng orihinal na impormasyon. Hindi sapat ang pagbura ng mga row o cell lamang. Hindi nito pinahahaba ang A o pinapayagang ilipat dito ang mga orihinal. Hindi awtomatikong humahaba ang takdang panahon ng aming tala ng kaso dahil nananatiling online ang isang pampublikong Issue.

C. Mga pangkalahatang tala ng pagpapahusay: mga sanhi at buod ng pag-aayos lamang ang maaaring panatilihin, nang walang pangalan, larawan, URL ng post, ID ng kaso, o ibang impormasyong matutunton pabalik sa orihinal na ulat. Hindi ito alternatibong imbakan para sa A o B.

Ang mga pagbubukod ay para lamang sa patuloy na pagsisiyasat o legal na pangangailangan. Itinatala ang dahilan, saklaw, at kondisyon ng pagtatapos at sinusuri ang mga ito sa pagitan na hindi lalampas sa 30 araw at sa pagtatapos ng pagsisiyasat. Kapag wala na ang pangangailangan, karaniwang kinukumpirma ang pagbura sa loob ng 30 araw, o sa orihinal na 90-araw na takdang panahon kung umiiral pa ito at mas maaga. Hindi awtomatikong nagsisimula muli ang mga takdang panahon sa muling pagbubukas o pagbubukod. Mga araw sa kalendaryo sa Asia/Tokyo ang ginagamit.

Saklaw ng mga takdang panahong ito ang mga talang kayang pamahalaan ng developer. Hindi ginagarantiya ng pagbura sa interface ng serbisyo ang pisikal na pagbura ng mga internal na recovery copy ng provider o backup ng device sa parehong panahon. Iba ang mga kopyang iyon at ang mga limitasyon sa pagbura sa mga talang nasa aming kontrol. Hindi nabubura ang mga naipadalang ulat kapag binura ang mga lokal na log ng app.

Para sa mga tanong o kahilingan sa pagbura, makipag-ugnayan sa tyamada.support@gmail.com. Ibigay lamang ang impormasyong kailangan upang matukoy ang kaugnay na kaso; huwag itong ilathala sa publiko.
