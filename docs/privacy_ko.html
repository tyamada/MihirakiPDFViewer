개인정보 처리방침

MihirakiPDFViewer는 기기에서 PDF를 편안하게 읽기 위한 앱입니다. 이 페이지에서는 앱이 어떤 정보를 처리하고 그 정보를 어떻게 사용하는지 설명합니다.

요약

앱의 기본 개인정보 보호 방침입니다.

PDF 내용은 외부로 전송되지 않습니다

선택한 PDF의 표시, 검색, 페이지 감지 및 관련 처리는 기기 안에서 수행됩니다.

광고 또는 분석 SDK 없음

이 앱에는 광고 전송이나 행동 분석을 위한 타사 SDK가 포함되어 있지 않습니다.

구입은 Apple이 처리합니다

앱 내 구입은 Apple의 StoreKit을 통해 처리됩니다. 앱은 결제 정보를 직접 받지 않습니다.

앱이 처리하는 정보

각 기능에서 사용될 수 있는 정보입니다.

PDF 파일

앱은 파일 선택기로 고른 PDF 파일을 엽니다. PDF 텍스트, 메타데이터, 페이지 정보는 보기 기능에 사용됩니다.

  • PDF 파일은 외부 서버로 업로드되지 않습니다.
  • iCloud Drive의 PDF는 Apple 시스템 동작에 따라 로드됩니다.
  • 보호된 PDF의 암호는 문서 잠금 해제에만 사용됩니다.

앱 설정

표시 설정, 표지 설정, 두 페이지 보기, 앱 아이콘 설정 및 유사한 환경설정이 기기에 저장될 수 있습니다.

  • 설정은 앱 동작을 복원하는 데 사용됩니다.
  • 설정은 개발자 서버로 전송되지 않습니다.

검색어

PDF 검색에 입력한 텍스트는 열린 PDF 안에서 검색하는 데 사용됩니다. 검색어는 외부 서비스로 전송되지 않습니다.

앱 내 구입

팁 구입 상태는 구입 후 UI와 앱 아이콘 변경에 사용될 수 있습니다.

  • 결제 정보는 Apple이 관리합니다.
  • 개발자는 신용카드 번호나 유사한 결제 세부 정보를 받지 않습니다.

지원 문의

GitHub Issues 또는 이메일로 지원팀에 문의하면, 답변하거나 문제를 조사하기 위해 필요한 범위에서 보내신 정보가 검토될 수 있습니다.

  • PDF 파일이나 그 내용을 보내지 마세요. 지원에 문의하기 전에 아래의 보고 및 이미지 안내를 확인해 주세요.
  • 기기 모델, OS 버전, 앱 버전, 재현 절차는 조사에 도움이 됩니다.

제3자와의 공유

사용자가 공유하거나 지원팀에 보낸 정보는 선택한 수신자에게 전달되며 수신자가 보관할 수 있습니다. StoreKit 구매와 iCloud Drive는 Apple의 처리 방식을 따릅니다. 샘플 다운로드와 외부 링크는 각 서비스 운영자에게 연결되며, 해당 서비스 및 선택한 공유 대상의 개인정보 처리 방침이 적용됩니다. 앱은 진단 결과를 개발자에게 자동 전송하지 않습니다.

보안

PDF 파일과 설정은 앱에 필요한 범위에서만 처리됩니다.

사용자가 관리하는 정보

PDF 파일과 암호는 사용자의 기기, iCloud Drive 또는 사용 중인 저장 위치에서 관리됩니다. 민감한 PDF를 다룰 때는 기기 암호, 생체 인증 및 iCloud 계정 보호를 켜세요.

방침 변경

이 개인정보 처리방침은 필요할 때 업데이트될 수 있습니다.

변경 안내

중요한 변경 사항은 이 페이지 또는 앱 안에서 안내됩니다. 최신 버전은 항상 이 페이지에서 확인할 수 있습니다.

기기 내 진단 및 앱 로그

진단 결과는 현재 화면의 메모리에 유지됩니다. 공유를 선택하면 검사 시각, 모델 이름과 모델 식별자(기기 고유 ID가 아님), OS 및 앱 버전, 전체·사용 가능한 메모리, 여유 저장 공간 검사를 제외한 결과가 포함됩니다. 로그에는 이벤트 유형, 시각, 개수, 경과 처리 시간이 기록됩니다. 앱에서 읽고 공유하는 로그는 최대 2,000개이며, 읽거나 기록할 때 24시간이 지난 항목을 제거합니다. 앱이 중지된 동안 타이머로 삭제하지 않습니다. 시스템 로그는 OS의 보관 규칙을 따릅니다. 결과와 로그는 자동 전송되지 않습니다.

문의

개인정보 관련 질문이나 삭제 요청은 지원팀에 문의해 주세요.

문의 방법

GitHub Issues 또는 이메일을 이용하세요. 공개된 장소에 게시할 때는 개인 정보나 PDF 내용을 포함하지 마세요.

지원 페이지 열기

개인정보 처리방침

설정 상단이나 앱 정보에서 개인정보 처리방침을 열 수 있습니다. PDF를 선택하기 전이나 읽는 중에도 구매나 로그인 없이 이용할 수 있습니다.

남은 저장 공간은 이 기기에만 표시됩니다. 공유하는 진단 텍스트에는 저장 공간 검사, 수치, 해당 검사가 종합 결과에 미치는 영향이 포함되지 않습니다. 로그에는 처리 경과 시간이 포함될 수 있지만 원시 시스템 가동 시간은 포함되지 않습니다.

읽기 복원을 위해 문서 북마크, 페이지, 표시 설정, 검색어를 기기에 저장하며 PDF 비밀번호는 저장하지 않습니다. 샘플 다운로드를 요청하면 GitHub Releases에 연결합니다. 이 방침이나 GitHub Issues를 열 때도 외부 사이트에 연결하며 운영자가 IP 주소와 요청 정보를 받을 수 있습니다. 보고서는 사용자가 선택한 대상으로 공유됩니다. 외부 서비스에는 해당 서비스의 개인정보 처리방침이 적용됩니다.

PDF 표시와 검색은 기기에서 처리합니다. 읽기 복원용 문서 북마크, 페이지 위치, 검색어, 표시 옵션은 로컬에 저장하지만 PDF 암호는 저장하지 않습니다. 문서를 닫거나 설정을 재설정하면 복원 기록이 삭제되지만 PDF와 진단 로그는 삭제되지 않습니다. 일부 가져온 PDF는 앱의 Documents 저장 공간에 복사됩니다. 로컬 앱 데이터를 삭제하려면 OS의 앱 삭제를 사용하고, 데이터를 유지하는 앱 정리 기능과 구분하세요. 외부 원본과 이미 공유한 사본은 삭제되지 않습니다. 로그 전용 삭제 버튼은 없습니다.

샘플 목록을 열면 앱이 GitHub에서 최신 카탈로그 JSON을 확인합니다. 업데이트에 실패하면 마지막으로 저장된 유효한 목록이나 앱에 포함된 목록을 사용합니다. PDF 파일은 사용자가 다운로드를 선택한 경우에만 다운로드됩니다. 카탈로그 요청은 raw.githubusercontent.com에 연결하고, PDF 다운로드는 GitHub Releases에 연결합니다. 이러한 서비스는 사용자의 IP 주소와 요청 정보를 받을 수 있습니다.

지원 정보의 보관

지원 정보는 답변, 문제 조사 및 기술적 성능 개선에만 사용합니다. 실명 입력을 요구하지 않습니다. 발신자의 표시 이름에 실명이 포함된 경우 답변과 조사에 필요한 기간 동안 원본 이메일 안에서만 보관하며, 사례별 Google Sheets나 개선 메모에 옮겨 적지 않습니다.

스크린샷은 원칙적으로 요청하지 않습니다. 글만으로 문제를 재현할 수 없고 이미지가 필요한 경우에만 tyamada.support@gmail.com으로 받습니다. 보내기 전에 PDF 내용, 파일 이름, 사람 이름, 알림 등 조사에 필요하지 않은 정보를 가려 주세요. 이미지는 원칙적으로 원본 이메일 안에서 처리합니다. 사례별 Sheets에는 이미지가 아니라 조사에 필요한 소견만 기록합니다.

GitHub 작성자의 이름이나 핸들을 사례별 Sheets나 개선 메모에 옮겨 적지 않습니다. 답변이나 조사에 필요한 경우에만 원본 Issue 링크를 사례별 Sheet에 보관합니다. 링크를 통해 작성자를 확인할 수 있는 동안은 작성자와 연결할 수 있는 정보로 취급합니다. 공개 Issue에는 개인정보, PDF 파일이나 그 내용, 파일 이름, 스크린샷을 게시하지 마세요.

GitHub의 공개 게시물과 개발자가 관리하는 이메일 및 사례 기록은 별개입니다. 사례 링크를 삭제해도 공개 Issue는 삭제되지 않습니다. 관리 범위 밖의 게시물이나 서비스 사본의 삭제는 보장하지 않습니다. 발신자를 다시 확인할 수 있는 보고와 사례 참조는 익명 정보로 취급하지 않습니다.

삭제 기산점 및 기한

A. 표시된 실명을 포함한 원본 이메일, 조사 이미지 및 조사용 사본: 답변이나 조사 결론이 있고 개발자가 남은 작업이 없음을 확인한 날을 사례 완료일로 봅니다. 답변이 없다는 이유만으로 자동 종료하지 않습니다. 기한을 매주 점검하고 완료 후 약 60일부터 삭제를 시작하여, 90일 이내에 관련 휴지통을 포함해 관리 가능한 기록의 삭제를 확인합니다. 60일은 최소 보관 기간이 아니며, 조기 삭제 요청을 통상 기한까지 기다리게 하지 않습니다.

B. 사례별 Sheets, 소견, Issue 링크 및 접수·삭제 기록: 원본 정보의 삭제가 완료된 날부터 90일 이내에 사례 파일과 관련 기록·참조의 삭제를 확인합니다. 행이나 셀만 삭제해서는 완료로 보지 않습니다. A의 기한을 연장하거나 원본을 이 기록으로 옮겨 보관하는 것을 허용하지 않습니다. 공개 Issue가 온라인에 남아 있어도 개발자의 사례 기록 기한이 자동 연장되지는 않습니다.

C. 일반화한 개선 메모에는 원인과 수정 요점만 남기며, 이름, 이미지, 게시물 URL, 사례 ID 등 원본 보고를 찾아갈 수 있는 정보를 포함하지 않습니다. A나 B 기록을 대신 보관하는 장소로 사용하지 않습니다.

예외는 계속되는 조사 또는 법적 필요성에 한정합니다. 이유, 대상 범위 및 종료 조건을 기록하고, 늦어도 30일마다 그리고 조사 종료 시 다시 검토합니다. 필요성이 사라지면 원칙적으로 30일 이내에 삭제를 확인하되, 원래의 90일 기한이 남아 있고 더 빠르면 그 기한을 적용합니다. 재개나 예외로 기한을 자동 재설정하지 않습니다. Asia/Tokyo의 달력 날짜를 기준으로 계산합니다.

이 기한은 개발자가 관리할 수 있는 기록을 대상으로 합니다. 서비스 화면에서 삭제해도 제공자의 내부 복구 사본이나 기기 백업이 같은 기간 내 물리적으로 삭제된다는 보장은 없습니다. 이러한 사본과 삭제 한계는 개발자가 관리하는 기록과 구분합니다. 로컬 앱 로그를 삭제해도 이미 전송한 보고는 삭제되지 않습니다.

문의나 삭제 요청은 tyamada.support@gmail.com으로 보내 주세요. 해당 사례를 식별하는 데 필요한 정보만 제공하고 공개된 장소에 게시하지 마세요.
