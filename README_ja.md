# 見開きPDFビューア

次回開発版の英語表示名は **Mihiraki: Two-Page PDF Reader**、日本語は **見開きPDFビューア**、韓国語は **미히라키 PDF 뷰어** です。他の言語名は `InfoPlist.xcstrings` に従い、未対応言語では英語へフォールバックします。プロジェクト名やURLは変更していません。

[English](README.md) | 日本語

右綴じの本（日本語の書籍など）の表示に適した、シンプルで直感的に
使えるPDFビューアです。

PDFを開くと、ページレイアウトとスクロール方向の設定を検出します。
PDFを単ページ表示または見開き表示で表示します。

このソフトウェアは生成AIを使用してコーディングしました。

## 機能

- **右綴じ・左綴じに対応**: PDFの方向設定に応じて、左右それぞれの
  読書方向に合ったページ移動ができます。右綴じ（R2L）の文書も、末尾へ
  ジャンプせず最初のページから開きます。
- **単ページ・見開き表示**: 縦長の閲覧領域では単ページ表示が
  デフォルトです。表示方法を切り替え、文書に合わせて表紙の扱いを調整できます。
- **検索とズーム**: PDF内のテキストを検索し、ピンチ操作で拡大して、
  拡大中のページをドラッグできます。
- **目次**: リーダーからPDFの階層付きアウトラインを開き、長い文書でも
  章や節を探して選択したページへ直接移動できます。
- **パスワード付きPDF**: 閲覧用パスワードが必要なPDFを開けます。
- **描画設定**: 必要に応じて、高画質レンダリングとシャープネスを
  設定できます。
- **読書位置の復元**: アプリを再起動したとき、最後に開いていた文書と
  ページから閲覧を再開できます。
- **ダウンロード可能なサンプルPDF**: 検証済みオンライン一覧、前回正常な保存済み一覧、同梱51件の一覧（PDF本体は同梱せず、利用時にダウンロード）を言語別に絞り込み、
  サンプルを端末へダウンロードして開いたり、不要なローカルコピーを削除したり
  できます。モバイルデータ通信でのダウンロード時には確認画面を表示します。
- **実機診断**: アプリ情報、ローカルストレージ、PDF描画のテストを端末上で
  実行できます。結果にはテスト日時、端末のモデル名とモデル識別子、OSとアプリの
  バージョンが含まれます。
- **プライバシーに配慮したアプリログ**: クラッシュ、スローダウン、操作や表示の
  不具合を調査するため、直近24時間の診断ログを表示・共有できます。生成ログに
  PDF本文、ファイル名やパス、検索語句、パスワードは記録しません。

テスト結果とアプリログは、共有ボタンを明示的に操作しない限り端末外へ送信されません。
自動送信機能はありません。ログは最大2,000件で、読込・記録時に24時間を超える記録を削除します。
アプリ停止中にタイマーで削除する仕組みではありません。

## 使い方

1. **PDFを開く**: ファイルピッカーを使って、端末またはiCloud Drive
   からPDFを選択します。他のアプリから送られたPDFも開けます。
2. **サンプルPDFを試す**: **サンプルPDFを見る**を選び、言語で絞り込んで
   サンプルをダウンロードします。同じ画面から開くことも削除することもでき、
   モバイルデータ通信でダウンロードする場合は事前に確認します。
3. **保護されたPDFを開く**: 閲覧用パスワードが必要な場合は、表示された
   画面に入力して**ロック解除**を選びます。
4. **ページを移動する**: スワイプまたはページスライダーを使います。
   ページ移動は、設定した左綴じ／右綴じの読書方向に従います。
5. **操作部を表示・非表示にする**: 文書をタップして、ツールバーと
   ページスライダーを切り替えます。
6. **拡大・移動する**: ピンチ操作で拡大または縮小します。拡大中は
   長押ししてからドラッグすると、ページ内を移動できます。
7. **検索する**: 検索欄にテキストを入力します。一致する文字列が文書内で
   強調表示されます。
8. **レイアウトを調整する**: 設定画面で単ページ／見開き表示、読書方向、
   表紙の扱いを選択します。「縦向きでは単一ページ表示」はデフォルトでオンです。
   縦長の閲覧領域では、iPadの幅広いレイアウトでも1ページずつ表示します。
   縦長の閲覧領域でも選択した見開き設定を維持するには、この設定をオフにします。
9. **描画を調整する**: PDFの文字や線を見やすくしたい場合は、設定画面で
   高画質レンダリングまたはシャープネスを有効にします。
10. **閉じる・再開する**: ツールバーから現在の文書を閉じられます。開いた
   まま終了した場合は、アプリの再起動後に同じページから再開できます。
11. **目次を使う**: リーダーのリストボタンからPDFの目次を開き、章や節を
    選択して該当ページへ移動します。目次を含まないPDFでは空状態を表示します。
12. **診断する**: 設定画面から**診断**を開き、**実機テスト**で端末・アプリ情報、
    メモリ、キャッシュ／空きストレージ、PDF描画を確認します。**アプリのログ**では
    直近の診断ログを確認でき、**問題を報告**ではGitHub Issuesへの報告準備ができます。
    結果やログは共有を明示的に操作した場合にのみ端末外へ渡されます。

## 価格と開発者の応援

見開きPDFビューアは無料で利用でき、広告はありません。PDFの閲覧、サンプルの
ダウンロード、ズーム、検索、
単ページ表示、見開き表示などの主要機能は、購入の有無にかかわらず
制限なく使えます。

App Store配布版では、StoreKitを使った非消耗型アプリ内購入として
サポーターアイコンを用意しています。購入は任意で、広告の非表示や
PDF閲覧機能の制限解除を目的としたものではありません。

応援画面の見出しは13言語共通でBronze・Silver・Goldです。価格はStoreKitから取得し、購入ボタンにだけ表示します。

実装で対応する非消耗型の応援アイテムは次の4種類です。

- `supporter_icon_bronze`: Bronzeアイコン
- `supporter_icon_silver`: Silverアイコン
- `supporter_icon_gold`: Goldアイコン
- `supporter_badge_koyomi_v2`: リリース記念こよみバッジ

Bronze・Silver・Goldを購入すると、対応する代替アプリアイコンを恒久利用できます。こよみは購入一覧に表示せず、代替アイコンは付属しません。次回開発版では既存・新規利用者を対象に、2028年1月1日00:00（日本時間）より前、すなわち2027年12月31日中までに端末時刻で判定して無料付与します。購入・コード・アカウント照会・通信は不要です。結果は端末内に保存し、期限後も保持します。新たな付与時に取得通知を表示し、アプリ情報の各バッジをタップすると拡大画像・名称・説明を表示します。

既存の有効なStoreKitバッジ権利は維持し、無料付与と合わせて1個だけ表示します。「設定 → 応援 → 購入を復元」は同じApple Accountの対象StoreKit購入を復元しますが、期限後に失った端末内の無料付与記録は復元しません。アプリ削除で端末内記録が失われる場合があります。対象購入のコード引換は応援画面から利用できます。

## インストール（ソース）

### 前提条件

- macOS 26.6
- Xcode 26.6（CI環境）または互換性のある新しい版。今回のローカル確認はXcode 27.1。

### コマンドラインでのビルドとテスト

Xcodeをインストールし、初回起動時の追加コンポーネント・iOSシミュレータを導入してください。`xcode-select -p`がXcodeのDeveloperディレクトリを示すことを確認します。Python 3は資料検査とシミュレータ選択に使用します。外部SwiftパッケージやCocoaPodsの取得は不要です。

```bash
git clone https://github.com/tyamada/MihirakiPDFViewer.git
cd MihirakiPDFViewer
xcodebuild -list -project MihirakiPDFViewer.xcodeproj
# Use a scheme listed above (CI when available; otherwise MihirakiPDFViewer).
xcodebuild build -project MihirakiPDFViewer.xcodeproj -scheme CI \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO
python3 scripts/ci_simulator.py
# Replace SIMULATOR_UUID with the SIMULATOR_ID printed by the command above.
xcodebuild test -project MihirakiPDFViewer.xcodeproj -scheme CI \
  -destination 'platform=iOS Simulator,id=SIMULATOR_UUID' \
  -only-testing:MihirakiPDFViewerTests CODE_SIGNING_ALLOWED=NO
```

シミュレータ用ビルドは作者の証明書・秘密鍵がなくても実行できます。実機へのインストールはXcodeで接続した端末を選び、Signing & Capabilitiesに自分のTeamと利用可能なBundle Identifierを設定してRunします。署名鍵・プロファイルはGitに登録しません。`Products.storekit/Configuration.storekit`はローカル試験用の公開可能な製品定義で、実購入の認証情報ではありません。

公開版を新規取得した際に`Assets.xcassets`や`AppIcon`が不足する場合、ソースだけではビルドできません。作者の秘密情報ではなく、リポジトリに含めるべき入力です。アセットを含む修正リビジョンを使用し、公開時には`MihirakiPDFViewer/Assets.xcassets/`、`Info.plist`、共有`CI.xcscheme`、`PrivacyInfo.xcprivacy`、追加したSwiftソースを同じコミットに含めてください。`CI`や検査スクリプトが存在しない古いリビジョンには、最新版のコマンドをそのまま適用できません。

### 継続的インテグレーション

GitHub Actions は `testing`・`main` への push と、両ブランチを対象とする
プルリクエストを検証します。ドキュメント変更時は、HTML の構造・内部リンク・
アンカー・画像参照をオフラインで確認します。アプリ・テスト・翻訳・プロジェクト
設定の変更時は、`macos-26` の Xcode 26.6 と iPad シミュレータ（iOS 26.5 以上）で、
共有 Scheme `CI` の単体テストを実行します。

`iOS checks` の手動実行で `ui_tests` を有効にすると、主要画面の UI テストも
3 件実行します。手動実行はワークフローがデフォルトブランチに入ってから利用でき、
実行対象に `testing` を選択できます。ログと `.xcresult` は 7 日間保存します。
GitHub Pages は引き続き `main` の `/docs` のみを公開し、検証処理では公開しません。
変更ファイルによる絞り込みで実行が省略されるため、必須チェックに設定する場合は
無関係なファイルだけを変更した PR の扱いを考慮してください。

ドキュメント検証は `python3 scripts/check_docs.py` でローカル実行できます。
明示的なタグの対応とローカルの `href`・`src` 参照を検証するもので、HTML 仕様への
完全な適合性や外部サイトの稼働状況は検証しません。
CI 設定をコミットする際は、共有 Scheme とアセットカタログも含めてください。
新規チェックアウトでもローカルと同じビルド用リソースが必要です。

### Xcodeでのビルド手順

1. アセットとリソースカタログを含めてリポジトリを取得します。
2. `MihirakiPDFViewer.xcodeproj` を開き、共有 `CI` スキームを選択します。
3. iOS/iPadOS 26.5以降のiPhoneまたはiPadシミュレータを選択して実行します。
4. 実機向けに署名する場合は開発チームを設定します。

アプリターゲットのリソースに `PrivacyInfo.xcprivacy` が含まれる必要があります。
ReleaseではArchiveと書き出したIPAの両方を確認してください。
